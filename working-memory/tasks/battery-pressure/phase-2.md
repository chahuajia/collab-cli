# 阶段 2 暴露点：余额 + 积分混合支付

**日期**：2026-09-17 ｜ **复杂点**：双资产账户 · 扣减顺序 · 退款拆账

## 场景边界

| 在范围内 | 不在范围内 |
| :--- | :--- |
| 购买 P1/P2 时余额+积分混合扣 | 信用/先用后付 |
| 积分不可提现、有有效期 | 积分获取规则（营销发券） |
| 全额积分 / 全额余额 / 混合 | 多级运营商分润 |
| 部分退款还原双资产 | 商城优惠券叠加 |

## 暴露点

| # | 检验什么 | 预期 KB |
| :-- | :--- | :--- |
| **P2-1** | 积分 ≠ 余额，独立 Account.type | design-decision |
| **P2-2** | 扣减顺序写死且可审计 | A10 规格先行 |
| **P2-3** | 退款按原路返还（LIFO 分录） | base-contract 不可变 |
| **P2-4** | 混合支付一条 Order 多条 LedgerEntry | INV-1 借贷平衡 |
| **P2-5** | 积分不足时整单失败（不全用余额补） | 显式策略，非隐式 |
| **P2-6** | 积分过期不可用于支付 | Entitlement 类比 |

## 已裁决策略（tick 1）

| 项 | 裁决 |
| :--- | :--- |
| 扣减顺序 | **先积分，后余额** |
| 退款顺序 | **先退余额，后退积分**（与扣减逆序） |
| 积分不足 | **拒绝订单**，不自动降级为纯余额（用户须改选） |

## 成功标准

1. 30 元订单：20 积分 + 10 余额 → 两条 LedgerEntry，账本平衡
2. 退款后积分/余额各自还原
3. 规格层定义清楚，无运行时代码
