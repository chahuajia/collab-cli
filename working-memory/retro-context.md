**证据**：`working-memory\` 的文件时间戳、三仓库 `git log`、`_experiment\` 的落盘产物

## 二、最具体的失效：working-memory 过期，且没人知道

三处互相不一致（子 agent 盘点时发现）：

| 文件 | 它说的 | 实际 |
| :--- | :--- | :--- |
| `README.md` | 活跃任务 = "D 实验第 2 轮：**待拍板**"；下一步读 `specs/round-2-diagnosis.md` | D 其实已完成 r1/r2；那份文件在 `_experiment\`，不在 `specs\` |
| `tasks/cli-development/anchors.md` | "下一个动作：`collab parse`" | `parse` 早已落地（`3162907`） |
| `tasks/cli-development/progress.md` | 标"进行中" | "进行中"栏是**空的** |

**根因不是"AI 懒"**：写工作记忆这个动作**没有任何时机绑定** —— 它靠"想起来"，
而长会话里最缺的就是"想起来"。

> **过期的工作记忆比没有工作记忆更坏**：它长得像"查过了"。

## 三、可优化项（按性价比排序）

1. **给工作记忆加"新鲜度自检"**（已落地）：`working-memory/check-freshness.mjs` ——
   拿 README 登记的 commit 跟三仓库实际 HEAD 比对。**过期从"感觉"变成"退出码"。**
2. **交接文档要有模板 + 校验**：至少含四项 —— 三仓库 HEAD / 未决项 / 下一步 / 陷阱。缺一项不算交接完。
3. **A16 的锚点应落在"任务目录"，不是集中式 working-memory**：
   这次真正起作用的锚点（判据表、基线）都在任务目录里 —— **因为任务产物天然会被打开**，
   而集中式工作记忆要靠"记得去读"。
4. **"实验装置"必须单独自检**（本轮最大教训）：
   五次失效**没有一次**是"处理"失败，全是**装置**失败 ——
   忘清 `target/`、删除留在 `git diff`、判据在隔壁、投递未达、brief 关掉处理组。
   → 装置必须能回答一句：**"它现在能失败吗？"**
5. **交接不要塞聊天记录**：给下一个 agent 只给**入口文档 + 文件路径 + `git log`**。

## 四、一句话

> **上下文处理的价值不在"管理对话"，在"把不可协商的东西从对话里搬出去"。**
> 搬对了（判据表、基线、驱动器）→ 压缩基本无感；
> 没搬（工作记忆停在 5 小时前）→ 新会话会**自信地走错方向**。
