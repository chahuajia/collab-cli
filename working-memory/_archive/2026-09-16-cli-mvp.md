## 二、判断台账：哪些被验证、哪些被推翻

### 被验证

| 判断 | 证据 |
| :--- | :--- |
| 协议按手册的速度长，会被稀释 | 约定 19 → 8；砍掉的 11 条**当天一次都没被用到** |
| 规则若不能自查，就会被表演 | 删掉"给鼓励""声明模式""配额递归轮数"——都能被"照做"而行为不变 |
| 错误前提会持续生产错动作 | `A16` 的 FIFO 前提 → "每 10 轮复述约束"（无效动作） |
| 环境型约束 > 规则 | 约定配额（`new agreement` ≥10 拒绝）是唯一"不是请求"的机制 |
| 生成物会过期 | `CATALOG_STALE` 上线当天抓到我忘了重生成 |

### 被推翻

| 当时的判断 | 推翻它的证据 |
| :--- | :--- |
| "链接必须用文件名，不能用 id" | Obsidian 实测：id 断链的成因是 **`aliases` 没登记** |
| "UTF-8 BOM 会导致乱码"（报告 #7） | 实测 139 个文件 **0 个带 BOM** |
| "`fix --dry-run` 退出码不一致" | 真相是**那个失败分支根本不可达**（死代码） |
| "A17 结束标记有笔误" | 实测两处都是 5 个 `=` |

**四次"报告说的 ≠ 实际存在的"** —— 报告是快照，代码和文件是现状。

## 三、踩的坑（每条带证据）

1. **工具与规则打架（两次）**：`renderIndex` 渲染 `[[id]]` 而规则禁 id；`collab new` 不写 `aliases`。
   → **工具每秒钟都在批量生产违规产物**，比文档写错危险得多。
2. **生成物没人负责刷新** → `CATALOG_STALE` + `apply` 自刷新。
3. **死代码假装成错误处理**：`evolution.yml` 的 `echo TODO`；`fix` 的 `unfixable`。
   **都躲过了测试 —— 因为没有测试问"这个分支什么时候会跑到"。**
4. **单一指标会以自己的方式变坏**：为满足"进度文档 ≤100 行"，归档脚本把头部（含 `更新` 日期与"当前阶段"）一起切走 → `collab memory` 当场抓出。
5. **"派出去" ≠ "已交付"**：2 个子 agent 投递未达、空转 25 分钟 → `patterns/parallel-work-needs-delivery-proof`。
